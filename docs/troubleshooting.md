# 故障排查

报告问题前，请记下 Winicode 版本、Windows 构建、目标应用及缩放比例。在“关于与诊断”中先预览报告，再导出需要提交的内容；删除可能涉及隐私的信息。问题入口为[项目 Issues](https://github.com/th-1056/Winicode/issues)。

| 现象 | 检查与处理 |
| --- | --- |
| 没看到 U+ 或 0 没有打开面板 | 确认使用新版微软拼音且其候选栏可见；查看托盘是否暂停、对应选项是否开启，以及目标应用是否被排除。先在 Winicode 输入测试区和记事本中复核。 |
| 关闭窗口后仍然运行 | 设置窗口关闭后保留托盘驻留。从托盘“退出”结束程序。 |
| 没有跟随 Windows 登录启动 | 安装版设置中开启登录启动，同时检查 Windows“应用 → 启动”中 Winicode 的状态。Windows 禁用后需在该页恢复。便携版不提供自启动开关。 |
| 设置无法保存 | 安装版检查个人数据目录是否可写；便携版完整移动到当前用户可写目录。先备份数据，避免覆盖尚未恢复的配置。 |
| 配置或词条损坏 | 先退出并备份个人数据目录，再查看程序的恢复提示及旁边备份文件。使用词条导出备份恢复前先检查文件内容。不要直接覆盖唯一备份。 |
| 字符显示为方框 | 目标字体可能缺少该码位。改用包含相应字形的字体，并检查实际码位。组合字符和控制字符可能没有独立可见字形。 |
| 插入失败或结果不确定 | 先检查原输入目标里的文本。焦点切换、管理员权限差异或应用限制可能影响发送；不要连续重试不确定结果。 |
| 更新检查不可用 | 核心功能可继续离线运行。手动访问项目 Releases，检查网络状态和 API 限流。更新检查只读取元数据。 |
| 升级提示无法退出 | 从托盘退出，关闭同一用户会话中的旧版 Winicode，再重试。安装器通过 `--exit --wait` 等待正常退出。 |
| 升级提示目录不符或便携版冲突 | 使用现有安装目录升级；便携版和安装版分开存放。需要迁移时先卸载并保留数据。 |
| 卸载因维护命令失败而停止 | 修复安装同一版本，再退出程序并重试卸载。先备份个人数据。程序文件缺失时不要手工删除注册表条目。 |
| Windows 提示来源或发布者未知 | 当前测试包未签名。核对项目来源、文件名和 SHA-256；无法确认来源时停止运行并联系维护者。 |

## 构建与打包

需要 Windows x64、PowerShell 7 和稳定版 .NET 10 SDK。CI 固定 10.0.402；本地脚本先查找 `.tools/dotnet/dotnet.exe`，再查找 PATH。应用项目和 `BuildInfo.Version` 的版本必须一致。

打包还需要预先准备的 Inno Setup 编译器，首选 7.1.0 x64，本地接受 6.7+。优先路径为 `.tools/inno/ISCC.exe`，随后使用 PATH。脚本不会运行编译器安装程序。草稿发布 CI 严格要求 7.1.0；runner 缺少该版本时需维护者先准备工具。

如提示 .NET 许可缺失，请使用包含根目录 `LICENSE.txt` 和 `ThirdPartyNotices.txt` 的官方 SDK 发行目录。Unicode 哈希失败时检查 `data/sources.json` 与文件是否来自同一个审核版本；不要将校验值直接改为失败文件的哈希。

同名 `dist/` 产物会阻止新打包。先将旧产物移到独立目录，再运行。失败的暂存目录位于 `artifacts/package-*`，可供核对；最终校验成功后才会将文件移入 `dist/`。

## 当前验证范围

记事本、浏览器、VS Code、Obsidian、100%/150%/200% 缩放、混合 DPI 多屏和 Windows 登录启动均在发布验收清单中。未经记录的组合属于待验证范围。管理员窗口、安全桌面、其他输入法、ARM64 和 x86 尚未声明支持。CI 构建与静态检查无法确认完整输入交互。
