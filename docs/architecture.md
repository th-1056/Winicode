# 架构与维护

Winicode 是 .NET 10 WPF 桌面应用，目标为 Windows 11 x64。主命名空间为 `Winicode`，应用和测试控制台不依赖额外 NuGet 包。程序入口、原生输入编排、服务和 UI 分层协作，公共控制器契约位于 `src/Winicode/Contracts.cs`。

| 位置 | 职责 |
| --- | --- |
| `src/Winicode/` | 程序生命周期、当前用户单实例/IPC、候选跟踪、输入缓冲、Unicode 检索和原生 Windows 交互 |
| `src/Winicode/Services/` | 数据路径、设置/别名持久化、登录启动、诊断和受限发布检查 |
| `src/Winicode/UI/` | 首次引导、设置页、托盘和主题 |
| `data/` | Unicode 18.0.0 原始官方文件、原许可、来源哈希和项目数学别名 |
| `tests/Winicode.Tests/` | 依赖为空的回归控制台，非零退出码表示失败 |
| `scripts/` | 构建测试、数据验证、打包、包验证和源码导出 |
| `installer/` | Inno Setup 源码、源文件白名单和安装器许可 |

## 运行状态与数据

输入流程需要保留原目标、区分发送失败与结果不确定的情况，避免自动重发造成重复内容。临时输入缓冲只在内存中使用。设置页通过 `IAppController` 调用服务，用户关闭设置窗口时托盘继续运行。

程序使用当前用户身份范围的单实例与命令通道。安装版和便携版共享输入实例所有权约束，避免同时安装两个输入钩子。维护命令必须在启动 UI、安装输入钩子之前完成：

| CLI | 维护契约 |
| --- | --- |
| `--settings` | 主动打开设置/首次引导 |
| `--background` | 登录启动时静默驻留 |
| `--exit --wait` | 请求当前用户实例退出并等待；没有实例时成功；超时或失败返回非零 |
| `--set-startup on` / `--set-startup off` | 调用应用的同一自启动逻辑；关闭时只移除本安装拥有的项 |
| `--cleanup-user-data` | 明确请求清理已知个人数据；拒绝任意路径、重解析点及越界清理 |
| `--self-test` | 无输入钩子的自检 |
| `--data-dir` | 测试专用的用户数据覆盖；安装器和正常发布入口不传该参数 |

`install-mode.json` 和 `portable.flag` 来自分开的打包暂存目录。安装版用户数据在 `%LOCALAPPDATA%\Winicode`；便携版在自身 `userdata/`。发布目录不包含默认个人配置。设置迁移的备份与原子替换由应用服务处理。

## 打包与安装

`package.ps1` 先执行构建测试，再以 `win-x64`、self-contained、无 trimming/单文件/AOT 的方式发布。随后复制公开说明、原始 Unicode 许可和 .NET 发行许可，写入构建来源清单，并复制成两个独立 payload。`payload-manifest.json` 记录所有其他包内文件的大小和 SHA-256。

Inno Setup 使用永久 AppId **`{5B1D09D9-5EAC-4D73-BC78-4F6F9E32A971}`**，当前用户最低权限、同一卸载登记和独立安装目录。升级会先比较版本并请求正常退出，保留数据和当前自启动状态。首次安装的启动选择调用应用 CLI；安装器不直接实现 HKCU Run 逻辑，也不修改 Windows 的 StartupApproved 状态。语义版本比较区分 Beta 数字标识和稳定版，阻止降级。

卸载先正常退出，再通过 CLI 关闭本安装拥有的自启动项。只有交互用户确认时才调用数据清理命令。Inno 按文件记录卸载，没有递归清空安装目录的通配规则，用户额外放入的文件会保留。

`verify-release.ps1` 读取 EXE 头与 ZIP，检查两项外部校验值、包内清单、模式、运行时和 Unicode 哈希，过程中不运行应用或安装器。它不解包检查压缩安装器内部，安装版暂存目录在交给编译器前检查。真实安装维护测试仍需独立 Windows 桌面。

## CI 与源码边界

CI 执行静态包装检查、Unicode 校验、应用构建和控制台测试。草稿发布仅由 `workflow_dispatch` 触发，要求引用已有版本标签和预先可用的 Inno Setup 7.1.0 编译器，创建 `draft: true` 的预发布说明与三项资产。公开发布由维护者另行执行。

源码导出使用明确文件白名单和限定源码树，拒绝链接、开发输出和常见敏感文件。内部计划、工具二进制、截图、日志、个人数据和构建结果均不进入导出。导出目录仍需人工审阅，再由维护者决定是否发布。
